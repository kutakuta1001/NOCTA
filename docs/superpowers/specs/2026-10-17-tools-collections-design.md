# Tools 欄のコレクション分類 — 設計

日付: 2026-10-17
対象: `website/index.html` の `#apps` セクション、`website/apps-data.js`、文言監査の仕組み（`scripts/copy-lint.py` / `claude-config/hooks/copy-audit-guard.py`）、新規 `docs/tools-collections.md`

## 意図

Tools が 13 個に増え、一列のグリッドでは何がどういう意図で並んでいるかが伝わらなくなった。
CEO の言葉では「初めて来た人がスクロールしてきて、まず『たくさんあるな』と見え、どれを触ろうかと考えたときに上のカテゴリーをふと見て、どんな意図で分類されているかが分かればいい」。
気になったコレクションを押すと、そのツールだけに絞り込まれる。

もう一つの目的は、今後ほかの作業フォルダのセッションがツールを足したときに、同じルールで分類されたカードとして並ぶこと。

## 3 つのコレクション

| key | 表示名 | 動詞（表紙の見出し） | 定義（CEO の説明を要約） | 現在のツール |
|---|---|---|---|---|
| `nuword` | NuWord Collection | 内省する | 心を静め、瞑想し、日々の気づきを捉え、点と点を線で結んでアウトプットを出す内省のためのシリーズ | before / still / Seed / Verse / Inner Canvas |
| `hina` | HiNa Collection | 集める | 石・花・世界など、世界にあるさまざまな観点を面白いと感じるために収集・観察する、収集欲を満たすシリーズ | Mado / Kai / Kihi / Hare / Ichi / Gyu |
| `yori` | Yori Collection | 学ぶ | CEO の趣味を土台に、それを深掘るためのアプリ。学習欲を満たすシリーズ（英語・作業タイマーなど） | lampnook / Barside |

- 動詞 3 語は CEO 確定
- 名前の付け方: NuWord と HiNa は「NuWord ○○」「HiNa ○○」と頭に付ける。Yori のツールは独立しているので名前をそろえない（CEO 確定）
- Yori という名前の由来は NOCTA のサイト・文書に書かない（CEO 指示）

## ゴール / 非ゴール / アンチゴール

ゴール
- 最初は 13 個すべてが見え、「たくさんある」と感じられる
- 押さなくても 3 つの分類とその意図が読める
- 表紙を押すとそのコレクションだけに絞り込める
- 新しいカードに分類を書き忘れたら、コミットの時点で止まる

非ゴール
- 各コレクションの専用ページ（`hina/`・NuWord の Vercel）の作り直し
- カード本体のデザインの刷新（タグの追加以外は今のカードのまま）
- 並び替え（新しい順など）の機能

アンチゴール
- 表紙が大きくてカードが画面の外に押し出され、「たくさんある」が見えなくなる
- 絞り込まないと分類が分からない（A 案のように意図が隠れる）
- 確定パレット（シルバー #B8B4AE × オフホワイト #E8E0D0）から外れた派手な色分け
- チェックが厳しすぎて、関係のない修正まで止まる

## 画面（C 案・表紙型。CEO 選択）

最優先の制約（CEO 確定）: 今のカード（サムネイル・グリッド・外観）は気に入っているので損ねない。表紙は小さく控えめにし、主役はあくまで今のカード。
- カードはサムネイル・大きさ・3 列グリッド・余白・ホバーを変えない。変えるのはバッジの文字と色だけ
- 表紙はカードより明らかに軽い見た目にする（低い高さ・細い枠・小さな文字）。PC で表紙を置いてもカードの 1 段目が見え始める高さに収める

見出し「TOOLS」と「Web Applications」の下に、表紙を 3 枚横に並べ、その下に今のグリッドを置く。

表紙 1 枚の中身
- 動詞（小さく・字間広め・コレクションの色）: 内省する / 集める / 学ぶ
- コレクション名: NuWord / HiNa / Yori
- 説明 1 行（日英）
- ツールの数（`apps-data.js` から数える）

動き
- 初期状態は何も選ばれておらず、全カードを表示する
- 表紙を押すと、そのコレクションのカードだけを残す。表紙は選択中の見た目になる
- 選択中の表紙をもう一度押すと全表示に戻る。全表示に戻るための「すべて」も置く（置き方は実装者に任せる）
- 選んだ状態は URL の hash に残す（`#apps-nuword` / `#apps-hina` / `#apps-yori`）。その URL で開くと絞り込まれた状態で `#apps` に着地する
- 表紙はボタンとして扱う（キーボードで押せる・`aria-pressed`）
- 各カードのバッジ（今は全部 "App"）をコレクション名に置き換え、色を表紙とそろえる

既存の「HiNa コレクション →」「NuWord コレクション →」ボタン
- 表紙と役割が重なるので見出し下からは外す
- 代わりに、選択中の表紙に小さく「コレクションのページへ →」を出す（`hina` → `./hina/`、`nuword` → `https://nuword-nu.vercel.app`、`yori` は専用ページがないので出さない）
- これは Claude の判断。リンク先がなくなると困る場合は CEO が戻せる

スマホ
- 表紙は縦に積まず、横 3 枚のまま小さくする（説明 1 行は省いてよい）。カードが下に押し出されすぎないため
- 横幅 16px の余白、横スクロールなし

色
- コレクションごとに 1 色。確定パレットに寄せたごく薄い色（叩き台: NuWord 暖かい生成り寄り、HiNa 淡い緑灰、Yori 淡い青灰）。具体値は実装者が決め、`docs/tools-collections.md` に記録する

日英
- 表紙の文言は `NOCTA_APP_COLLECTIONS` から描画し、英語切替はカードと同じ方式（日英を data 属性に持たせ `setLang` で入れ替える）に載せる

## データ

`apps-data.js` の各オブジェクトに `collection` を足す。値は `"nuword"` / `"hina"` / `"yori"` のいずれか。

- 今の `cat: "app"` は使い道がないが、`data-acat` で参照されているので残す（消すかどうかは実装者に任せる）
- コレクションの定義（表示名・動詞・説明・色・専用ページの URL）は `apps-data.js` の中に `NOCTA_APP_COLLECTIONS` として置く。ページとチェックの両方がここを正とする
- 表紙の説明 1 行は、カードと同じ `descJa` / `descEn` というキー名で書く。こうすると既存の文言監査（`apps-data.js` の `descJa` / `descEn` の行が変わったら監査を求める）がそのまま表紙にも効く。動詞と表示名も日英を `NOCTA_APP_COLLECTIONS` に置き、`index.html` の辞書には持たせない（Claude の判断）
- 表紙の並び順は NuWord → HiNa → Yori。カードの並びは今の配列順のまま

ページ側の安全策: `collection` がない、または未知の値のカードは「すべて」のときだけ表示し、バッジは "App" のままにする。ページは壊さない。

## 今後ツールを足すときのルール

### 文書: `docs/tools-collections.md`（新規）

書くこと
- 3 コレクションの定義と見分け方（迷ったときの問い: 「静めて線にする」なら NuWord、「観点を集めて眺める」なら HiNa、「趣味を深掘って学ぶ」なら Yori）
- どれにも当てはまらない・2 つにまたがると感じたら、勝手に決めずに CEO に聞く
- カードの必須項目（`title` / `collection` / `url` / `imgUrl` / `descJa` / `descEn` ほか今の項目）と、バッジは自動でコレクション名になるので手で書かないこと
- 名前の付け方（NuWord / HiNa は頭に付ける。Yori は自由）
- 追加位置は配列の先頭
- 新しいコレクションを足すとき・名前を変えるときは CEO の判断が要ること

参照を張る場所
- `website/CLAUDE.md`（HP のファイルを触るセッションが自動で読む）の apps-data.js の行
- `apps-data.js` 冒頭のコメント

### コミット時のチェック

`scripts/copy-lint.py` に分類の検査を足し、`copy-audit-guard` が `apps-data.js` を含むコミットで実行する。

- 止める条件: カードに `collection` がない / `NOCTA_APP_COLLECTIONS` にない値
- 止めたときのメッセージ: どのカードか、使える値、`docs/tools-collections.md` を読むこと
- 分類の検査は文言監査の印（`--mark`）とは別物として扱う。分類が正しくなるまで印があっても止める（実装方法は実装者に任せる）
- 読み取りに失敗したとき: `apps-data.js` がステージされているコミットに限り、止める側に倒す（fail-closed）。それ以外のコミットでは分類の検査自体を走らせないので、関係のない修正は止まらない。既存の文言監査の fail-open はそのまま（Claude の判断）
- `apps-data.js` には `sync-brand.mjs` が書き換える `/* strategy-name:start */` のような目印コメントがある。読み取りはこれに耐えること
- hook はどの作業フォルダのセッションからの NOCTA へのコミットにも効く（グローバル hook のため）。ソースは `claude-config/hooks/`、配置は `~/.claude/hooks/` へ cp

対象は Claude Code のセッションからのコミットだけでよい（ツールを足すのはほぼ Claude Code のセッション。CEO 確定）。git の pre-commit hook は入れない。

入れないもの: GitHub Actions での公開前チェック。失敗すると本番が更新されず、関係のない修正まで止まるため（Claude の判断）。

## 品質と確認

- 実装前に `frontend-design:frontend-design` を呼び、`~/designer/INDEX.md` に該当パターンがあれば適用して used_in を記録する（R-17）
- 表紙とカードの文言は `copy-auditor` で監査し、CEO の OK のあとで印を付ける（R-02b）
- 確認: 全表示・各絞り込み・もう一度押して解除・hash 付き URL で開く・英語切替・スマホ幅・`collection` なしのカードを一時的に入れたときの表示とコミット時の停止
- push は CEO の指示があるときだけ

## 実装者に任せること

- 表紙の細かい見た目（余白・字の大きさ・選択中の表現）、絞り込みのアニメーション
- 「すべて」の置き方
- 色の具体値
- `cat` を残すか消すか
- チェックを copy-lint.py と hook のどちらに書くかの分担
