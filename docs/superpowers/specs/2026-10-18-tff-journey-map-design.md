# 旅の地図（The First Flower の「行った場所のベストショット」）設計書

日付: 2026-10-18 / 状態: CEO レビュー待ち（ビルダー確認・Codex レビュー反映済み）

## 1. 意図

The First Flower（`website/the-first-flower/`）の Profile の横から入る、作者が今まで行った地域のベストショットを見せるページ。

- 訪れた人が地図で地域を押すと、その地域の景色の写真が大きく出て「行ってみたい」と思う。作者自身はその写真で思い出が少しよみがえる。この 2 つを同じ一枚で叶える。
- Google フォトの地図機能との違いは 2 点。主役が人物ではなく地域の景色であること。各地域の写真が 2〜3 枚に絞られ、作者が選んだものだけが見えること。
- 旅に出て写真が増えるたびに、各地域の写真と地域そのものが増えていく構想。

## 2. 目標 / 非目標 / 避けたいこと

目標
- 作者の写真ライブラリ（Google フォト・約 18,000 枚）から、地域ごとに候補を作り、作者が選んだ 2〜3 枚だけを公開する。
- 公開後も、新しい旅の写真を足して選び直せる。

非目標
- Tools（`apps-data.js`）への掲載。このページは TFF の一部として置く。
- Google フォトとの常時同期。公開する写真は選んだ時点でサイトに複製する。
- 人物写真の公開。

避けたいこと（技術的に動いても失敗とみなす）
- 人が主役の写真が地域の代表として出る。
- 撮影場所の情報（GPS）が公開する写真に残る。
- 18,000 枚を作者が 1 枚ずつ見る作業になる。

## 3. 制約（確定）

- Google Photos Library API は 2025-03-31 以降、アプリ自身が上げた写真しか読めない。Picker API は作者が選んだ写真を渡せるが、ダウンロードした写真から撮影場所が消され、URL は 60 分で切れる。**よって候補作りに API は使わず、Google Takeout の書き出しを入力にする。** Takeout は写真ごとに `*.supplemental-metadata.json`（緯度経度・撮影日時）を付ける。
- 処理はすべて作者の Mac のローカルで、無料で動く道具だけで行う（有料 API を使わない）。空きディスクは約 488GB。
- 元の写真・Takeout・候補の作業ファイルは git に入れない（リポジトリの外に置く）。git に入れるのは公開する縮小版の写真とデータだけ。1 ファイル 1MB を超えない。
- サイトは GitHub Pages・Tailwind CDN・相対パス（`website/CLAUDE.md`）。push は CEO の指示があるときだけ。
- Takeout の書き出しと、写真の採否は作者が自分で行う。

## 4. 決まったこと（CEO の決定）

### 4-1. 地域の単位
- 日本は都道府県、海外は国。
- 写真が多い地域だけ、一段下の地点に分ける（例「北海道 › 小樽」「京都 › 嵐山」）。

### 4-2. 訪れた人が見るページ（比較案 A「地図から選ぶ」を採用）
- 左に日本地図、右に写真。行った都道府県はピンク（`tff-rose`）、いま見ている地域はマゼンタ寄りの紫（`tff-accent` #B168A8）。
- 地域を押すと右に大きな一枚、その下に 2〜3 枚の送り。地点があれば地点名で切り替える。
- 写真の下に地域名と撮影年月。作者が書いた写真にだけ短いひとこと（例「運河の夜」）を出す。
- 地点に分けた地域では、地図で地域（例「北海道」）を押すと、作者が地点の写真から選んだ代表 2〜3 枚を出す。地点名を押すとその地点の 2〜3 枚に切り替わる（Claude の判断。CEO が変更可）。
- 採用が 0〜1 枚の地域・地点は公開しない（下書きのまま）。候補が足りなくても自動で写真を埋めない。
- 地図の上に「日本 / 世界」の切り替え。世界は国単位。小さい国でも押せるよう、地図と同じ選択状態を持つ地域の一覧を添える。
- スマホは地図が上・写真が下の縦並びで、押すと写真まで流れる。
- 配色・書体は TFF と同じ（紫×クリーム。`website/the-first-flower/DESIGN-NOTES.md` の 2・3 章）。入口は TFF の Profile 節に置くリンク。

### 4-3. 作者が選ぶ作業
- 候補は 1 地域（地点がある場合は地点ごと）20 枚まで。
- 候補作りで自動的に外すもの: 人の顔が大きく写った写真 / ブレ・暗すぎ / ほぼ同じ写真の連続。残りを景色らしさで順位付けして上位 20 枚。
- 写真がたくさん集まる場所は地点の候補として提示し、分けるかどうかは作者が決める（自動で細かく切らない）。
- 選ぶ画面はローカルのブラウザ。地域ごとに 20 枚が並び、押して 2〜3 枚を選ぶ。その場でひとことを書ける。
- 選んだ写真だけを縮小し、撮影場所の情報を消して `website/` 側に書き出す。
- 自宅周辺の除外設定は不要（作者は自宅周辺で写真を撮っていない）。
- 自動で外した写真は削除せず「理由つきの候補外」として残し、作者が確認して候補へ戻せる。暗さの判定で夜景を落とさない。
- 人が主役でないことの最終確認は、作者の採否で行う（顔検出は候補の絞り込みにだけ使う）。
- 一度却下した写真は、次回以降の候補に出し続けない。

### 4-4. 撮影場所の情報がない写真（CEO 決定: 手で地域を付ける）
- 2013 年ごろの一眼レフ（`DSC_xxxx`）など、撮影場所のない写真は捨てずに「地域未設定」に入れる。
- 選ぶ画面で作者が地域・地点を手で付ける。18,000 枚から 1 枚ずつ付ける作業にならないよう、撮影日ごとにまとめて表示し、1 日分をまとめて地域に付けられるようにする（Claude の判断）。
- 地域を付けたあとは、撮影場所のある写真と同じく候補作りに入る。
- 実データ（2026-10-19 集計）: 写真 44,230 枚（重複を除く・動画を除く）、撮影場所あり 15,901 枚。撮影場所のない写真は 3,435 日分ある。1 日ずつ付けるのは現実的でないため、次のように進める（CEO 決定 2026-10-19）。
  - 同じ日に撮影場所のある写真がある日（1,570 日・14,775 枚）は、その日の地域を「たぶんここ」として先に入れ、作者が日ごとにまとめて確かめる。
  - アルバム名が旅先のもの（屋久島・NewYork・香港 マカオ など）は、地域の候補として出す。
  - 残りの日（1,865 日・13,554 枚）は最初は出さず、作者が思い出せる旅だけあとから開いて付ける。
- Google の顔の判別結果（Takeout の `people`・9,419 枚）を、人が写っている写真の印として使う。

### 4-7. バックアップ用の整理（CEO 依頼 2026-10-19・優先度低）
- 重複をなくした写真ライブラリを 1 つのフォルダにまとめ、作者がそのフォルダを個人の HDD にコピーすればよい状態にする。

### 4-5. 入力の元
- 主は Google フォト（Takeout）。ライブラリに他人が撮った写真（共有アルバム・パートナー共有）は入っていない（CEO 確認済み）。
- Flickr の公開写真も少しだけ使う（CEO: 極力選ばないが少しは選ぶ）。Flickr の写真は撮影場所が消えていることが多いので、4-4 と同じく作者が地域を付ける。公開するときは他の写真と同じく縮小版をこのページ用に置く（Claude の判断）。

### 4-6. 増やし方
- 初回は Takeout の全書き出し。以降の新しい旅は、その旅の写真を手元のフォルダに入れて同じ手順を回す。入力は Takeout の書き出し（写真＋ JSON）と、写真アプリからの書き出し（写真そのものに撮影情報が入った JPEG / HEIC）の両方を受け付ける。Takeout の「定期エクスポート」（2 か月ごとに新しい分を書き出す）も選択肢として使える。
- 既に選んだ写真は保持し、その地域に候補を足して選び直せる。

## 5. 作るうえで守ること（Codex レビュー 2026-10-18 を反映）

- **撮影場所を公開しない（最重要）**: 公開処理は「採用写真を再エンコード（回転は画素に適用してから） → 大小すべての書き出し画像に EXIF / XMP / IPTC 等の位置・機器情報が残っていないか検査 → 公開データが許可した項目だけか検査 → 書き出すファイルの一覧が公開データと一致するか検査 → 配置」に固定する。どれかに失敗したら公開用ファイルを更新しない。Takeout の JSON・作業ファイルを `website/` に置かない（`website/` は丸ごと公開される）。
- **入力の例外**: 画像と JSON の対応が一意でないもの・壊れたもの・撮影日時のないものは捨てずに保留にし、実行ごとに件数を報告する。撮影年月はファイルの更新日時で代用しない。緯度経度の欠損を 0 で埋めない。動画は対象外。
- **地域の判定**: 版を固定した行政境界データ（都道府県・国）で包含判定する。境界付近・海上など曖昧なものは保留にし、作者が直す。作者の手直しは自動判定より常に優先して保存する。地域は表示名ではなく固定の ID（例 `JP-01`）で持ち、地点も固定 ID と親地域を持つ。
- **選んだ結果を守る**: 写真はファイル内容のハッシュで識別し、同じ写真の二重取り込みを防ぐ。採用・却下・ひとこと・地域の手直しは候補の順位とは別に保存し、候補を作り直しても消えない。採用を外した写真は公開側からも消す。公開処理は一時領域で完成させてから入れ替え、途中で失敗したら前回の状態を残す。
- **選ぶ画面の安全**: `127.0.0.1` だけで待ち受け、起動ごとの合言葉（トークン）を付ける。写真は登録済みの ID でだけ返し、任意のパスは受け付けない。外部のスクリプトを読み込まない。
- **ひとことの扱い**: 公開データは JSON シリアライザで書き出し、ページでは `textContent` で表示する（文字列連結や `innerHTML` を使わない）。
- **重さ**: 判定は縮小した画像で行い、結果を写真のハッシュ単位でキャッシュして途中から再開できる。似た写真の比較は撮影日時や特徴の近いものに絞る。公開ページは選んだ地域の写真だけを読み込む。
- **地図の状態**: 写真のない地域・読み込み中・読み込み失敗を表示で区別する。素早く押し替えたとき、前の地域の読み込みが後から上書きしない。キーボードで地域を選べる。
- **工程を分ける**: 取り込み / 地域判定 / 候補評価 / 採否の保存 / 画像の書き出し / 公開、を別々に動かせるようにし、合成した試し用写真で各工程を確かめられるようにする。写真・状態・キャッシュはリポジトリの外に置き、git にはコードと試し用データだけを入れる。

## 6. ビルダーの判断に任せること

- 逆ジオコーディング（緯度経度 → 都道府県・国）の方法。オフラインで動くこと。
- 顔・ブレ・重複の判定と景色らしさの順位付けの具体的な手法（ローカル・無料の範囲で）。
- 公開データの形式（`tff-` 系の既存データファイル `tff-gallery-data.js` などに倣った JS ファイルを想定）と、ページ・画像の置き場所（`website/the-first-flower/` 配下を想定）。
- 公開画像のサイズと画質（大きい写真と小さい送り用。1 ファイル 1MB 未満）。
- 選ぶ画面の作り（ローカルの簡易サーバー + HTML など）と、ローカル道具の置き場所（リポジトリ内の公開されない場所）。
- 新規 UI なので、実装前に `frontend-design:frontend-design` とデザイナーハーネス（`~/designer/INDEX.md`）を通す（R-17）。

## 7. 進め方

Takeout の書き出しは数時間〜数日かかるため、待つあいだに訪れた人向けの地図ページ（試し用データ）を先に作り、書き出しが届いたら実データで撮影場所の有無の比率や形式を確かめてから候補作りの手法を決める。
