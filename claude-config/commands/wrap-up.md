# /wrap-up [対象名（省略可）]

今回のセッションで行った作業を振り返り、
取扱説明書（README/ガイド）と引き継ぎ書（プロジェクトごとの handoff）を更新する。
handoff の宛先は作業中のプロジェクトに応じて自動解決する（複数ターミナル/プロジェクト対応）。

---

## Step 0: 今回の作業を把握する

以下を確認して今回の作業内容を把握する:

1. 現在の会話履歴から今回行ったことを特定する
2. 引数があれば `TARGET = 引数`、なければ会話から自動判定する

**主要ターゲットの判定ルール:**
- `~/.claude/commands/` に新しいスキルを作った → `TARGET = スキル名`
- `~/research/` にリサーチ結果を作った → `TARGET = research`
- NOCTA プロジェクト（楽曲/HP/ベストプラクティス）の作業をした → `TARGET = nocta`
- 複数に該当する場合 → すべてを対象にする

**作業プロジェクトの判定（handoff の宛先解決に使う）:**
- `PROJECT_ROOT` = `git rev-parse --show-toplevel`（git 管理下でなければ現在の作業ディレクトリ）
- このスキルは複数のターミナル/プロジェクトで使われる。handoff は固定パスではなく、下記 Step 1 の解決順で**そのプロジェクトの引き継ぎ場所**に書く。

---

## Step 1: handoff（引き継ぎ書）を更新する

handoff の宛先と形式は**プロジェクトごとに異なる**。固定パスを使わず、次の解決順で決める。

### 1-A. 宛先と形式の解決（上から順に最初に当てはまったもの）

1. **プロジェクトの CLAUDE.md に引き継ぎ書の規約が書かれていれば、それに従う**
   - 例: nuword (`PROJECT_ROOT/CLAUDE.md`) は「引き継ぎ書: ルート直下の `引き継ぎ書_YYYY-MM-DD*.md`」→ **日付別ファイル型**（新規ファイルを作る）。
2. **既存の引き継ぎ書ファイルがあれば、その形式に合わせる**
   - `PROJECT_ROOT` 直下に `引き継ぎ書_*.md` が複数ある → **日付別ファイル型**（最新の1本を Read して体裁を踏襲し、新規作成）。
   - `handoff.md`（`PROJECT_ROOT/handoff.md` または `PROJECT_ROOT/project_*/handoff.md`）が1本ある → **追記型**（末尾追記）。
3. **NOCTA プロジェクト**（作業ディレクトリが `~/NOCTA` 配下、または `TARGET = nocta`）→ `~/NOCTA/project_NOCTA/handoff.md` に**追記型**。
4. いずれも該当しなければ `PROJECT_ROOT/handoff.md` を**追記型**で作成。

判定に迷う場合のみ、解決した宛先パスを1行提示してから書く（それ以外は確認を取らない）。

### 1-B. 追記型（handoff.md に1行追記）

1. ファイルを Read する
2. 今回の作業を1〜3行で要約して**末尾に追記**する（既存行は書き換えない）

**追記フォーマット（R-06 に従う）:**
```
YYYY-MM-DD: [完了した事実の要点]。次: [次に取るべきアクション]。
```

### 1-C. 日付別ファイル型（引き継ぎ書_YYYY-MM-DD_<トピック>.md を新規作成）

最新の既存 `引き継ぎ書_*.md` を1本 Read して体裁（見出し・「完了した事実」「成果物」「次のアクション」節）を踏襲し、`PROJECT_ROOT/引き継ぎ書_YYYY-MM-DD_<トピック>.md` を新規作成する。

**共通の書き方ルール:**
- 「何をしたか」の事実を数値・固有名詞を使って具体的に書く
- 「なぜしたか」「どうやったか」は最小限（追記型は1〜3行以内）
- 絵文字は使わない
- 次のアクションがない場合は「次: なし（完結）」

### 1-D. 古い引き継ぎ書のアーカイブ（日付別ファイル型のみ）

新規の引き継ぎ書を作成した後、`PROJECT_ROOT` 直下の `引き継ぎ書_*.md` を数える:

1. **11本以上ある場合のみ実行**する（10本以下なら何もしない）
2. `mkdir -p PROJECT_ROOT/docs/handoffs` を実行する
3. 日付の新しい5本を残し、それ以外を `git mv` で `docs/handoffs/` に移動する（git 管理外なら `mv`）
4. `docs/handoffs/INDEX.md` を更新する（無ければ新規作成）。形式: `- [ファイル名](ファイル名) — 冒頭の要点1行`。移動したファイル分だけ追記し、既存行は書き換えない
5. 完了報告に「アーカイブ: N本 → docs/handoffs/」を含める

移動はコミットしない（ユーザーが次のコミットに含める）。

## Step 2: README.md を生成・更新する

### ケース A: `TARGET = research` または `/research` スキルを作った

**対象ファイル:** `~/research/README.md`

ファイルが存在するか確認する:
- 存在しない → 新規作成
- 存在する → 内容を Read して、今回の作業で変わった部分のみ更新する（全書き換えしない）

**README.md に含める内容:**
1. `/research` スキルの概要（1〜3行）
2. 基本の使い方（コマンド例3〜5個）
3. フォルダ選択フロー（ケースA/B/Cの説明）
4. 出力ファイルの構造（フォルダツリー）
5. Obsidian への追加方法
6. 制約・除外ルール（表形式）
7. 収集上限
8. 関連スキル（使い分け表）

### ケース B: `TARGET = スキル名`（`/research` 以外の新スキル）

**対象ファイル（解決順）:**
- NOCTA 作業時 → `~/NOCTA/project_NOCTA/drafts/[スキル名]-guide.md`
- それ以外 → `PROJECT_ROOT/docs/[スキル名]-guide.md`（`docs/` が無ければ `PROJECT_ROOT/drafts/`）

新しいスキルの使い方ガイドを生成する。含める内容:
1. スキルの目的・概要
2. 実行方法（コマンド例）
3. 生成されるファイルの説明
4. 注意点・制約

### ケース C: 上記 A/B 以外（既存プロジェクトの機能追加・修正など）

README/ガイドの新規作成は行わない。
Step 1 の handoff 更新のみで完了とする（NOCTA・nuword 等いずれのプロジェクトでも同様）。

---

## Step 3: 完了を伝える

```
wrap-up 完了
更新ファイル:
  - 引き継ぎ書: [解決した実パス]: [追記/作成内容の1行サマリ]
  - README/ガイド: [生成した場合のみ・ファイルパス]
  - アーカイブ: [実行した場合のみ・N本 → docs/handoffs/]
```

---

## IMPORTANT（制約）

- CLAUDE.md・スキルファイルを自動変更しない
- `approved/` への書き込みをしない
- 追記型 handoff への追記は末尾のみ（既存行を書き換えない）。日付別ファイル型は新規作成のみ（既存の引き継ぎ書ファイルは書き換えない）
- handoff は固定パスを使わず、必ず Step 1-A の解決順で宛先を決める（NOCTA 以外のプロジェクトで NOCTA の handoff に書かない）
- README/ガイドは全書き換えより差分更新を優先する
- 引数なしで実行した場合は会話から自動判定する（確認を取らない）
