依頼パターンを分析し、改善提案をまとめてください。

## Step 1: /insights を実行する

このセッションで /insights がまだ実行されていない場合は実行する。
すでに実行済みの場合はその結果を利用する。

## Step 2: 過去のレビューレポートを読み込む

`project_NOCTA/drafts/` 内の `interaction-review-*.md` を Glob で検索し、
最新の1件を Read で読み込む。存在しない場合はスキップ（初回実行）。

## Step 3: git履歴からパターンを分析する

以下を実行（project_NOCTA ディレクトリ内）:

```bash
# 直近30コミットの日時・種別
git log --oneline -30 --format="%ad %s" --date=short

# 変更頻度の高いファイル（繰り返し作業の特定）
git log --oneline -50 --name-only --format="" | grep -v "^$" | sort | uniq -c | sort -rn | head -15
```

## Step 4: パターンを分析する

以下の観点で分析する:

**依頼の傾向**（/insights データから）
- 主な作業カテゴリ（ブログ投稿・楽曲制作・設定変更・システム構築など）
- 1セッションあたりのメッセージ数・コミット数
- 繰り返し依頼しているタスク（スキル化できる候補）

**摩擦ポイント**（問題の再発チェック）
- 過去レビューで指摘された問題が改善されているか
- git履歴に現れる「fix:」「hotfix:」「修正」系コミットの頻度

**強みのパターン**（継続すべき良い習慣）

## Step 5: レポートを作成する

`project_NOCTA/drafts/interaction-review-[今日の日付YYYY-MM-DD].md` に保存:

```
# インタラクションレビュー: [YYYY-MM-DD]

## サマリー（2行以内）

## 今回の主な作業パターン
| カテゴリ | 観察された傾向 | 前回比 |
|---------|--------------|-------|

## 継続すべき強み
1.
2.

## 改善提案（優先度順）
| 優先度 | 現状の習慣 | 改善案 | 期待効果 |
|--------|-----------|--------|---------|
| 高 | | | |
| 中 | | | |

## スキル化・自動化の候補
（繰り返し依頼しているタスクでスキルがまだないもの）
1.
2.

## /insights からの主要な指摘（3点以内）
1.
2.
3.

## 前回からの改善状況
（前回レポートとの比較 / 初回の場合は「初回」と記載）
```

## Step 6: コミットする

```bash
git add project_NOCTA/drafts/interaction-review-*.md
git commit -m "docs(review): インタラクションレビュー [YYYY-MM-DD]"
git push origin main
```

コミットメッセージに「Co-Authored-By:」を含めないこと。

## Step 7: 完了を伝える

「インタラクションレビュー完了
レポート: drafts/interaction-review-[日付].md

主な改善提案:
1. [上位提案]
2. [2番目の提案]

次回実行目安: 4週間後に /interaction-review を実行してください。」

IMPORTANT:
- CLAUDE.md・スキルファイルを自動変更しない（提案のみ）
- APIキー・パスワードをレポートをに含めない
- /insights はローカル環境でのみ実行可能（リモートエージェントでは使用不可）
