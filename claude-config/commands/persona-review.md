# /persona-review — ペルソナ分離レビュー

未コミット差分（または指定対象）を、観点の異なるペルソナのサブエージェントに並列レビューさせ、指摘を統合して報告する。

**設計原則（厳守）:**
- **根拠必須**: 根拠のない指摘を出させない。全指摘に `file:line` または再現手順を必ず添える。根拠を示せない懸念は「未確認事項」に分離する
- **推測で埋めない**: 仕様が不明な点は指摘にせず「未確認事項」として列挙する
- **責務分離**: ペルソナは指摘のみ行い、修正はしない。修正は本体セッションが指摘を受けて判断する
- **正常系に偏らない**: 各ペルソナは自分の観点の異常系・破壊操作を優先する

## ペルソナ定義

| # | ペルソナ | 観点 |
|---|---------|------|
| P1 | 新人ユーザー | 直感操作で壊す。想定外の順序・空入力・戻るボタン・リロード・未ログイン状態での操作 |
| P2 | せっかちなベテラン | 高速連打・二重送信・IME変換中の確定・同時タブ操作・レースコンディション |
| P3 | 悪意ある第三者 | 境界値・権限外アクセス・インジェクション・CSRF/認証バイパス・他人のリソースIDの直叩き |
| P4 | 整合性監査役 | DBスキーマとコードの突合。NULL/型不一致・トランザクション欠如・部分失敗時のデータ欠損 |
| P5 | 回帰番人 | 変更が周辺機能に与える影響。共有コンポーネント・共通API・既存テストとの整合 |
| P6 | 仕様懐疑者 | 一次情報（計画書・CLAUDE.md・スキーマ定義）と実装の突合。仕様と成果物のズレ |

## 手順

### Step 1: 対象とペルソナを決める

- 引数なし → `git diff HEAD` + 未追跡ファイル（`git status --porcelain`）を対象にする
- パス指定あり → そのファイル群を対象にする
- 計画書パス（`docs/superpowers/plans/` 配下）あり → P6 に計画書を渡す

**ペルソナ選定（既定は3体、`--all` で6体）:**
- API・認証・DB変更を含む → P3, P4, P5
- UI・フォーム変更を含む → P1, P2, P5
- 計画書がある実装 → 上記 + P6
- 判断に迷えば P3, P4, P5

### Step 2: ペルソナを並列起動する

選定したペルソナを **1メッセージ内で並列に** Agent 起動する。各エージェントへのプロンプトには以下を必ず含める:

1. ペルソナ設定（上表の観点をそのまま渡す）
2. 対象の diff またはファイルパス一覧（エージェント自身に Read させる）
3. 出力契約: 「指摘は `[重大度] 指摘内容 — 根拠: file:line または再現手順` の形式。修正はしない。根拠を示せないものは『未確認事項』として分離。0件なら『指摘なし』と返す」
4. 重大度定義: 🔴 データ破壊・セキュリティ・本番障害 / 🟡 エッジケースの誤動作 / 🟢 改善余地

### Step 3: 統合する

全ペルソナの結果を回収し:
1. 重複指摘をマージする（複数ペルソナが同じ箇所を指摘 = 重大度を1段引き上げ）
2. 根拠のない指摘が紛れていたら「未確認事項」に降格する
3. 重大度順に並べる

### Step 4: 報告する

```
## ペルソナレビュー結果（N体 / 対象: <差分 or パス>）
| 重大度 | 指摘 | 根拠 | ペルソナ |
|--------|------|------|---------|
| 🔴 | | file:line | P3 |

## 未確認事項（根拠を示せなかった懸念・仕様不明点）
- <内容> — 確認方法: <どうすれば白黒つくか>

## 指摘なしの観点
- P5: 指摘なし
```

修正の実施可否はユーザー（または本体セッションの判断フロー）に委ねる。

## 既存フローでの位置づけ

```
実装 → /persona-review（観点別・ユーザー/攻撃者視点） → 修正 → /codex-diff（Codex・コード品質視点） → コミット
```

- Codex レビューは「第三者のコード品質・設計」視点、persona-review は「使う人・壊す人・仕様」視点で補完関係
- Easy タスクには使わない（レビュー過剰）。認証・DB・課金・公開系の変更で使う

## 注意

- ペルソナは Sonnet（既定モデル）で起動する。6体全部で1回あたりのコストが大きいので、既定は3体
- 対象 diff が 2000 行を超える場合は分割を提案する
- 各ペルソナには修正権限を与えない（Edit/Write を使わせない）
