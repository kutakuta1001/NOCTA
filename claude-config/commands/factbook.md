# /factbook — 経営向け三点セットの作成・改訂

**規則の正本は `~/consulting/_firm/playbooks/executive-factbook.md`。開始時に必ず全文を Read し、
全工程でこのプレイブックに従う。**本スキルは工程の段取りだけを定め、規則は重複記載しない。
書式・チーム規約は `~/.claude/commands/references/consulting-common.md`、
ファクト規律は `~/facts` の台帳と `/facts` に従う。

## Step 0: モード判定

1. `~/consulting/` 配下に進行中のファクトブック案件（deliverables/ に factbook 系の正本がある engagement）
   があるかを確認する。会話の文脈が既にその案件なら確認せず継続する
2. **改訂モード**: 進行中の案件があり、引数が修正指示（または空）→ Step R へ
3. **新規モード**: 引数が新しい議題 → Step N へ。どちらか曖昧なときだけ1回で聞く（G-04）

## Step N: 新規立ち上げ

1. consulting-common.md のエンゲージメント規約で `~/consulting/[slug]/` を作り、engagement.md を初期化
2. **目的・読者・当日の問い**の3点を確認する（自明な項目は聞かない）
3. 三点セットの器を最初から分けて作る:
   - ①詳細版 = `deliverables/[date]-[slug]-factbook.md`（正本。全経緯を記録）
   - ②要点版・③説明版 = 正本から派生。**③は初版から「削るものルール」を適用した状態で出す**
     （情報を残す方に倒さない。往復の半分は初版で削っておけば消える）
4. 検査の器も同時に作る:
   - `analysis/verify-consistency.py`（①②③の数値・件数・確定事項の突き合わせ）
   - `analysis/guards.py` 相当（③の禁止表現＋自己テスト。live-showcase の実装を雛形にコピーして育てる）
   - 図は `analysis/gen-fig-*.py` → SVG（数値・衝突・禁止語の assert を生成側に埋める）
5. ③の生成系は live-showcase の `analysis/build-explainer.py` を雛形にする
   （ORDER/SECTION の2箇所替え・連番 assert・印刷目次・PNG 差し替えの口 `pngfig()` を含む）
6. 初版ができたら Step C（共通仕上げ）へ

## Step R: 改訂

1. **CEO の指示を逐語で `inputs/ceo-answers-*.md` に保存してから**着手する（要約すると決定の根拠が消える）
2. 指示を分解し、計算が絡むものは先に検算スクリプト（assert つき）で固めてから本文と図を直す
3. CEO が PPTX を直接編集して戻してきた場合は、**文言をそのまま**反映する（言い換えない）
4. ③から内容を消す指示のときは、**先に①へ保存してから消す**。削除のたびに空参照を grep で確認
5. 数値の定義に触れる指示（単価・比率・閾値）は、**素案・正本の該当定義を Read で確認してから**直す
   （思い込みで直すと表記揺れを再生産する）
6. Step C へ

## Step C: 共通仕上げ（毎版必ず全部やる）

1. 検算スクリプト実行 → ③build（assert）→ ①②③整合検査 → 横断スイープ（撤回済み表現の残存）
2. PDF 2種（目次つき／**目次なし・print-color-adjust 強制**）＋ PPTX を生成し、PPTX 検査（溢れ・取りこぼし）
3. **変更したページを画像レンダリングして目視する**（ラベルの重なり・空参照・図の崩れは目視でしか捕まらない）
4. **`/codex-review` を2回転**。🔴は反映または却下理由つきで①の履歴に記録
5. ①の改訂履歴に「CEO指示の逐語＋何をどう変えたか＋検算スクリプト名」を記録し、
   handoff.md を更新（G-05）
6. 納品報告に G-06 のデブリーフを付ける（単発の微修正には付けない）

## イメージ図の依頼を受けたとき

Claude Design は使わない（CEO決定）。**自己完結の入力 Markdown** を deliverables/ に作って
ChatGPT・NotebookLM・Gemini 系に渡してもらい、戻った PNG は `analysis/` に上書き → 検品
（誤字・余計なバッジ・冗長ヘッダー）→ 修正点を入力 md に記録。手順の詳細はプレイブック参照。

## やらないこと

- 説明版に経緯・版差分・長段落を「念のため」残すこと（既定は削る）
- 未確認の費目を0円として単一値を出すこと（レンジ＋「上限ではない」の明示）
- ブラウザ印刷を案内すること（目次なしPDFを渡す）
