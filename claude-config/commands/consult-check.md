# /consult-check — 精密チェック機構（仮想コンサルチーム）

対象ドキュメントを観点の異なるチェッカーに並列レビューさせ、指摘を統合して報告する。
/persona-review のドキュメント版。出力契約・重大度は
`~/.claude/commands/references/consulting-common.md` の「出力契約と重大度」に従う。

**設計原則（/persona-review と同一・厳守）:**
- 根拠必須: 全指摘に位置（ファイル・スライド番号・行）or 再現手順を添える。示せない懸念は「未確認事項」へ
- 推測で埋めない・チェッカーは指摘のみ行い修正しない
- 指摘0件の観点は「指摘なし」と明記する

## チェッカー定義

| # | チェッカー | 観点 | 必要ツール |
|---|-----------|------|-----------|
| K1 | ファクトチェッカー | 全事実主張・引用・統計・URLの実在と内容一致を WebSearch/WebFetch で照合。出典なし断定の検出 | WebSearch, WebFetch, Read |
| K2 | ロジックチェッカー | ピラミッド構造・MECE・論理飛躍・So What 欠落・結論と根拠の不整合・隠れた前提・選定された型の要素に空欄や未検証変数が隠されていないか（consulting-common.md「型カタログ」参照） | Read |
| K3 | 数値チェッカー | 全計算（合計・比率・成長率・加重スコア）を Bash で再計算。単位・桁・期間の整合、前提値の現実性（Sanity Check） | Read, Bash |
| K4 | レッドチーム | 結論への最強の反証・実行可能性・見落としリスク・逆インセンティブ・「うまくいかない世界」の想定 | Read, WebSearch |
| K5 | 表現チェッカー | 1スライド1メッセージ・アクションタイトル・用語統一・読者適合・3ラベル原則の表記遵守 | Read |

## Step 1: 対象とチェッカーを決める

- 引数にパスあり → そのファイル（複数可）
- 引数なし → 直前に作成・議論していた成果物（会話文脈から特定。特定できなければ CEO に確認）

**選定規則（既定3体、`--all` で5体）:**
- 数値・データ中心（財務モデル・市場推計・KPI報告） → K1, K3, K4
- 構成・提言中心（戦略デック・提案書・計画書） → K2, K4, K5
- 判断に迷えば → K1, K2, K4

対象が2000行を超える場合は分割を提案する。

## Step 2: チェッカーを並列起動する

選定したチェッカーを **1メッセージ内で並列に** Agent 起動する（subagent_type: general-purpose。
K1/K3 が WebSearch・Bash を要するため）。各エージェントへのプロンプトに必ず含めるもの:

1. チェッカー設定（上表の観点をそのまま渡す）
2. 対象ファイルのパス（エージェント自身に Read させる）
3. consulting-common.md「出力契約と重大度」を Read して従う指示
4. 出力契約: 「指摘は `[重大度] 指摘内容 — 根拠: 位置 or 再現手順`。修正はしない。
   根拠を示せないものは『未確認事項』に分離。0件なら『指摘なし』と返す」
5. K1 には追加指示: 「照合できなかった出典は誤りと断定せず『未確認』として列挙」
   K3 には追加指示: 「再計算はすべて Bash（bc / python3）で実行し、計算式と結果を根拠に含める」

チェッカーには Edit/Write を使わせない（読み取り・検証のみ）。

## Step 3: 統合する

1. 重複指摘をマージする（複数チェッカーが同じ箇所を指摘 = 重大度を1段引き上げ）
2. 根拠のない指摘が紛れていたら「未確認事項」に降格する
3. 重大度順に並べる

## Step 4: 報告する

```
## 精密チェック結果（N体 / 対象: <パス>）
| 重大度 | 指摘 | 根拠 | チェッカー |
|--------|------|------|-----------|
| 🔴 | | スライド3 / L42 | K3 |

## 未確認事項（照合不能・根拠を示せなかった懸念）
- <内容> — 確認方法: <どうすれば白黒つくか>

## 指摘なしの観点
- K5: 指摘なし
```

修正の実施可否は CEO（または呼び出し元フロー）に委ねる。修正後の再チェックは指摘のあったチェッカーのみ再起動する。

## 既存フローでの位置づけ

- ドキュメント・提案・計画・分析 → **/consult-check**（本スキル）
- コードの差分 → /persona-review（ユーザー/攻撃者視点）・/codex-diff（Codex・品質視点）
- /consult-deck・/consult-analyze の納品前ゲートとしても呼ばれる

## 注意

- チェッカーは general-purpose（既定モデル）で起動する。5体全起動はコストが大きいので既定は3体
- 対外提出・経営会議・金額の大きい判断の資料には `--all` を推奨
- 検算で使った計算ログは対象と同じディレクトリの analysis/（なければ作成）に保存させる
