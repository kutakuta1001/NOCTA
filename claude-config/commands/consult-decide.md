# /consult-decide — 判断の助け（仮想コンサルチーム）

意思決定をコンサルの型で支援する。**判断の代行はしない**: 推奨+根拠+リスクまで出し、決定は CEO が行う。
規約・書式は `~/.claude/commands/references/consulting-common.md` に従う。

## Step 0: 引数検証とフレーミング材料の確認

1. 引数が空なら「迷っている決定を指定してください。例: `/consult-decide 事業Aの継続可否`」と表示して終了
2. 次の3点を確認する（文脈から自明な項目は聞かない）: 決定期限 / 不可逆性（あとで引き返せるか）/ 制約（予算・人・既定路線）
3. 出力先エンゲージメントを決める（/consult-deck の Step 0 と同じ規則）

## Step 1: WRAP フレーミング（選択肢を広げる）

`consultant-em` を Agent tool で起動する。渡すもの: 決定内容・選択肢・制約・engagement.md のパス。
指示: 「まず consulting-common.md の『型カタログ』から、この決定がどの型のどの変数の問いかを特定する
（例: 参入判断ならリーンキャンバスの『圧倒的優位性』と『顧客セグメント』が主変数）。
決定を型の変数として位置づけてから、WRAP の W（Widen）を実施。決定を『何を最大化/回避する決定か』に再定義し、
既存選択肢を整理した上で、**検討されていない第3の選択肢を必ず1つ以上追加**する
（組み合わせ案・時間差案・小さく試す案など）。二者択一のまま進めない」

## Step 2: 意思決定マトリックス

1. EM の出力から評価基準4〜8個と重み案を作り、CEO に提示して確認する。
   一括委任時・無応答時はデフォルト重みで進め、**重みを変えたら結論が変わるか**（感度）を必ず併記する
2. スコアリングは `consultant-em` に依頼し、加重合計は Bash（bc / python3）で検算する。検算ログは analysis/ に保存

## Step 2.5: ビジネスケース（高額・投資性の判断のみ）

金額の大きい投資判断では、consulting-common.md の「ビジネスケース書式」（前提表・3〜5年P/L×シナリオ3本・
感度表・ROI）の作成を CEO に提案する。作成は consultant-analyst（計算スクリプトを analysis/ に保存）。

## Step 3: プレモーテム

`consultant-partner` を起動する。渡すもの: マトリックス結果と有力案。
指示: 「有力案について『この決定は失敗した』と仮定し、原因を5つ以上列挙 → 各原因を
軽減策（事前に打てる手・早期警報指標）に翻訳。R（現実検証）と P（間違いへの備え）を兼ねる」

## Step 4: Debate（高リスク時のみ）

**発動条件（いずれか）:** 不可逆な決定 / 金額・工数が大きい / 対外的な影響（公開・契約・信用）がある。

1. general-purpose エージェント2体を**1メッセージ内で並列**起動: 賛成役（有力案を通す最強の論証）と
   反対役（有力案を止める最強の論証）。互いの存在を伝え、根拠必須・印象論禁止を指示する
2. `consultant-partner` に両論をジャッジさせる: どちらの論証が強いか・決め手・残る不確実性

低リスクの決定では Debate を省略する（コスト過剰）。

## Step 5: 納品

1. 「レコメンデーションメモ書式」で `deliverables/[日付]-[決定slug]-decision-memo.md` を作成
   （作成は consultant-em。パートナーの推奨・確信度（高/中/低）・残論点・未検証変数一覧を含める）。
   **「成功の定義」節（経済的用語・測定指標・測定時期・測定方法）を必ず含める** — /consult-steerco の
   定例レビューでこの節と実績を答え合わせする
2. engagement.md を更新
3. CEO に報告: 推奨と確信度 / 結論を変えうる感度（重み・前提）/ CEO が最終判断すべき残論点（価値判断・トレードオフ）

## IMPORTANT（制約）

- 判断を代行しない。「決めました」ではなく「推奨します。残る価値判断はこれです」と報告する
- 前提の信頼度レベル（事実/推定/仮説）をメモに明記する
- 迎合禁止: マトリックスやプレモーテムが CEO の当初意向と逆を示したら、そのまま提示する
- 議題の事実関係が未整理なら、先に /consult-analyze を提案する
- 開始時に `~/consulting/_firm/knowledge.md` があれば Read し、既知の事実を再調査しない
- 対外・高額・不可逆の決定メモは、納品前に `/codex-review [パス]`（Codex 第三者レビュー）を CEO に案内する

## 棲み分け

- 自分の価値観・判断軸で考えたい → /kabeuchi
- 外部の批判的視点と対話したい（メモ不要） → /consult-sparring
- 決定の材料となる分析が未了 → /consult-analyze
