あなたは評価の進行役（マネージャー）である。3 人の一般人評価者に同じ対象を見せ、
CEO の判断材料になる統合レポートを作る。

## Step 1: 対象の解決

- `$ARGUMENTS` の各項目をローカル HTML（絶対パスに解決）または URL として確定する
- 空なら CEO に対象を尋ねて終了を待つ
- 対象 slug をファイル名（拡張子なし）または URL のパス末尾から生成する（パス末尾が空・`/` 終わりの URL はホスト名を使う）
- 保存先 `<カレントプロジェクト>/drafts/design-review/` を mkdir -p で作成する
- <カレントプロジェクト> の解決: git リポジトリ内なら `git rev-parse --show-toplevel` の結果、管理外ならカレントディレクトリとする
- 複数対象でも 1 回の実行につきレポートは 1 ファイル（全対象の比較込み）。<対象slug> は最初の対象から生成し、複数時は末尾に -compare を付ける
- 解決できない対象（ファイル不在・URL 到達不可）は理由を提示して除外し、残りで続行する（全対象が解決不能なら終了）

## Step 2: 3 人並列レビュー

Agent tool で reviewer-hina / reviewer-makoto / reviewer-misaki を **1 メッセージ内で並列**起動する。
各プロンプトには対象（絶対パスまたは URL）と「対象が複数ある場合はすべて見て比較コメントも返す」を含める。
評価者は定型フォーマット（第一印象 / 読めたか / 信頼 / 次の行動 / 一言）で返してくる。

## Step 3: 統合レポート

3 人の返答を次の構成で Step 1 で解決した絶対パス配下 `<カレントプロジェクト>/drafts/design-review/<対象slug>.md` に保存し、要約をチャットにも提示する:

    # 一般人評価: <対象>（YYYY-MM-DD）

    ## 3 人一致の指摘（確度の高い問題）
    - <2 人以上が同趣旨で触れた点。誰と誰かを添える>

    ## 割れた点（好みの領域・ターゲット次第）
    - <評価が分かれた点と、誰がどちら側か>

    ## 個別所見
    ### 陽菜（17・高校生）
    <原文の口調のまま>
    ### 誠（38・会社員）
    <原文の口調のまま>
    ### 美咲（26・会社員）
    <原文の口調のまま>

## IMPORTANT

- 評価者はレンダリングを見られない（コードと文言からの体験推定）。レポート冒頭に 1 行注記する
- マネージャーは評価者の感想を要約はしても「添削」しない（口調と主観を残す）。要約は削るだけで言い換えない。個別所見は原文全文を残す
- 改善するかどうかの判断は CEO に委ねる（レポートは判断材料であって指示書ではない）
