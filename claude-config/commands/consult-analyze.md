# /consult-analyze — 分析（仮想コンサルチーム）

コンサルチームの仮説駆動プロセスで分析する。規約・書式は
`~/.claude/commands/references/consulting-common.md` に従う。

## Step 0: 引数検証と段取り

1. 引数が空なら「分析したい事柄を指定してください。例: `/consult-analyze 解約率上昇の要因`」と表示して終了
2. 出力先エンゲージメントを決める（/consult-deck の Step 0 と同じ規則: 既存文脈があれば流用、なければ slug 規則で新規作成し engagement.md 初期化）
3. CEO 提供の関連資料・データがあるか確認し、あれば inputs/ に置いてもらう（既にあれば省略）
4. `~/consulting/_firm/knowledge.md` があれば Read し、既知の事実を再調査しない
   （Step 2 の analyst への指示にも関連する既知事実を含める）

## Step 1: 論点整理とワークプラン（ゲート）

`consultant-em` を Agent tool で起動する。渡すもの:
- 分析対象・文脈・inputs/ の一覧、engagement.md のパス
- 指示: 「consulting-common.md の『型先行プロトコル』ステップ1〜3を実行: イシュー定義 →
  型選定（型カタログから・理由付き）→ 全要素を3ラベル+空欄で充填 → 感度ランキング。
  型の空欄・仮説（=変数）を行としたワークプラン（変数×検証方法×必要データ×感度・
  ワークストリーム3本以内、感度『高』上位1〜2個を優先実査）を作成。
  イシューツリーは型の要素分解として使う」

**ゲート:** ワークプランを CEO に提示し承認を待つ。一括委任時はデフォルト続行を明記。
巨大すぎる議題（ワークストリーム4本超が必要）は、スコープを絞る分割案を提示して CEO に選ばせる。

## Step 2: 並列分析

`consultant-analyst` をワークストリーム単位で起動する（**上限3体・1メッセージ内で並列**）。各体に渡すもの:
- engagement.md のパス、担当ワークストリーム（ワークプランの該当行）、出力先 `analysis/`
- 指示: 「3ラベル原則・出典必須・Bash検算必須。仮説に不利な反証データも必ず探す。
  完了時に analysis/[ワークストリーム名].md へ保存」

大規模・多源泉の事実検証が必要な場合（例: 論争的なテーマ、10源泉超の突合）は、
deep-research スキルの利用を CEO に提案する（コスト大のため勝手に起動しない）。

## Step 3: 統合（Synthesis）

`consultant-em` を起動する。渡すもの:
- analysis/ の全分析メモ、初期仮説
- 指示: 「メモ間の矛盾を明示的に解消し、仮説の採否を判定。SCQA でストーリー化し、
  発見をビジネスインパクト（売上・コスト・リスク・時間）に翻訳。『分析レポート書式』でドラフトを analysis/draft-report.md に保存」

## Step 4: パートナー検証

`consultant-partner` を起動し、Sanity Check（前提・桁・現実性）とレッドチーム（結論への最強の反証）を実施させる。
- 🔴 は EM に修正させ再判定（最大2ラウンド）。🟡 は修正 or 「前提と判断」節に明記
- パートナーの反証が立った場合、無理に元の結論を守らない。結論を修正するか両論併記で CEO に提示する

## Step 5: 納品

1. 完成版を `deliverables/[日付]-[テーマslug]-analysis.md` に保存
2. engagement.md を更新（進捗・決定事項・次アクション各1〜3行）
3. CEO に報告: エグゼクティブサマリー・仮説の採否・未検証変数一覧（感度付き）・未確認事項・追加分析の選択肢
4. ファームナレッジへの昇格0〜3件（事実と検証済みの学びのみ・`_firm/knowledge.md` へ）

## IMPORTANT（制約）

- 仮説駆動だが確証バイアスに注意: analyst には反証データの探索を必ず指示する
- 事業性・投資判断が絡む分析では、consulting-common.md「ビジネスケース書式」の利用を検討する
- 分析メモに無い数値を統合段階で創作しない
- 未確認事項を隠さない（納品物の独立した節として明示する）
- 続けて資料化する場合は /consult-deck、判断に進む場合は /consult-decide を案内する

## 棲み分け

- 単発のウェブ調査（分析不要） → /research
- 音楽トレンド調査 → /phase1-trend
- コード・実装の調査 → 通常の Explore/general-purpose エージェント
