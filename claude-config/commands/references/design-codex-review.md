# デザイン抽出物の Codex 批評規約（design-codex-review）

/design-extract と /design-promote が Codex 批評を行うときの共通規約。
呼び出し基盤の詳細（認証・フォールバック・使用量）は ~/.claude/references/codex-review-setup.md を参照。

## 呼び出し方法

必ず ~/designer をカレントディレクトリにして custom モードで呼ぶ
（codex-review.sh はカレントの git リポジトリルートを作業対象にするため）:

    cd ~/designer && ~/.claude/scripts/codex-review.sh custom "<プロンプト>"

認証フォールバック: 終了コード 75 または出力に CODEX_AUTH_FAILED を含む場合、
ChatGPT Plus 連携が切れている。勝手に従量課金へ切り替えず、必ずユーザーに確認してから
CODEX_AUTH=apikey で再実行する（/review スキルと同じ運用）。

## 通常批評テンプレート（/design-extract 用）

以下の <> を埋めて custom モードに渡す:

    あなたはデザインエンジニアのレビュアーです。このリポジトリの次のファイルをレビューしてください:
    - レシピ: patterns/<slug>.md
    - デモ: demos/<slug>.html（レシピの frontmatter に demo がある場合のみ）
    - 元記事の要点: <抽出時に得た要点を 3〜5 行で>

    観点:
    1. 再現忠実度: 元テクニックの核心を外していないか
    2. 汎用性: 特定サイト依存の値（固有の色・寸法・文言）のハードコードがないか
    3. コード品質: prefers-reduced-motion 対応・パフォーマンス・アクセシビリティ
    4. 抽出漏れ: 上記要点のうちレシピ化されていない価値あるテクニックがないか

    出力: 指摘を Critical / Warning / Nit の 3 段階に分類し、各指摘に修正案を 1 行添えてください。

## 厳格批評テンプレート（/design-promote 用）

通常批評テンプレートの全文（レビュアー役の宣言文・ファイルリスト・出力指示を含む）をベースに、以下の 2 点を変更して渡す:

- 観点 1〜4 の後に次の 2 観点を追加する:

    5. スキル化適性: 適用条件が明文化されているか。指示文として曖昧さがないか
    6. 副作用: グローバル配置した場合に他プロジェクトの既存デザインルールと衝突しないか

- ファイルリストの「元記事の要点」の行を「起案した昇格物の全文: <昇格物のテキストをここに貼る>」に差し替える

## 指摘の反映ルール

- Critical: 必ず反映する
- Warning: 採否を理由つきで CEO に提示する（/design-promote ではグローバル影響のため原則反映）
- Nit: 任意（軽く触れるだけで良い）
- 複数パターンを一括抽出した場合は 1 回の custom 呼び出しにまとめる（使用量節約のため）
