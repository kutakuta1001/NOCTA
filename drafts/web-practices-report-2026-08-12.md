## 要注意: git・シェル操作に関わる提案（CEOが内容を確認してから判断）

以下は Web ページ側の主張として収集されたもので、**自動適用していません**。

1. **`.claudeignore` の新規作成**（クエリ1）
   - ファイル作成自体は安全だが、除外パターンを誤ると Claude が必要なファイルを読めなくなる。特に `drafts/` を丸ごと除外すると context.md / handoff.md 以外の草案が参照できなくなり R-05 の運用に影響する
   - 判断: 除外対象を「バイナリ素材とアーカイブ済みノート」に限定し、`.gitignore` の内容をそのまま流用しないこと。作成前に対象一覧を CEO に提示する

2. **`sandbox.filesystem.denyWrite` の設定**（クエリ3）
   - OS レベルでファイルシステムアクセスを制限する強力な設定。v2.1.223 で「`denyWrite` が作業ディレクトリを含むとサンドボックス化コマンドが起動しない」不具合が修正されており、設定範囲を誤ると Bash が動かなくなる
   - 判断: 導入するなら `outputs/approved/` のみを対象にし、作業ディレクトリ全体を含めない。段階的に検証する

3. **`MAX_THINKING_TOKENS` の設定**（クエリ5）
   - Opus 5 / Sonnet 5 / Fable 5 は拡張思考（budget_tokens）を**サポートしていない**（適応的思考 + `/effort` で制御）。この環境変数は現行モデル構成では効果がないか、意図しない挙動を招く
   - 判断: 採用しない（下記「適用しない項目」参照）
