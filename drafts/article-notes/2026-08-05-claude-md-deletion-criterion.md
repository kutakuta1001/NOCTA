## 要約（3〜5行）
公式ベストプラクティスは、CLAUDE.md の各行について「これを削除すると Claude が間違いを犯しますか？」と問い、そうでなければ削除せよと明言している。膨らんだ CLAUDE.md は Claude が実際の指示を無視する原因になる。CLAUDE.md はすべてのセッションで読み込まれるため、広く適用されるものだけを入れ、ドメイン知識やときどきしか関連しないワークフローは skills に移す。CLAUDE.md はコードのように扱い、定期的に削除し、Claude の動作が実際に変わるかで変更をテストする。

## 主なポイント
- 削除基準: 「削除したら Claude が間違うか」→ 否なら削除
- 含める: Claude が推測できない Bash コマンド / 既定と異なるコードスタイル / テスト指示 / リポジトリのエチケット / プロジェクト固有のアーキテクチャ決定 / 環境の癖 / 明白でない落とし穴
- 除外する: コードを読めば分かること / 標準的な言語規約 / 詳細な API ドキュメント / 頻繁に変わる情報 / 長い説明やチュートリアル / 「きれいなコードを書く」のような自明なプラクティス
- 診断: ルールがあるのに従わない → ファイルが長すぎてルールが埋没している
- 診断: CLAUDE.md に書いてあることを Claude が質問してくる → 表現が曖昧
- ときどきしか使わない知識は skills へ（オンデマンド読み込み）
