## 要約（3〜5行）
`claude --permission-mode auto -p "..."` のように非対話実行で auto mode を使うと、
分類器が繰り返しアクションをブロックしたときにフォールバックするユーザーがいないため、auto mode は中止する。
無人実行では「分類器が判断に迷ったら止まる」という前提で設計する必要がある。

## 主なポイント
- auto mode の分類器はスコープエスカレーション・未知のインフラストラクチャ・敵対的なコンテンツ駆動のアクションをブロックする
- 対話セッションではユーザーにフォールバックするが、`-p` ではフォールバック先がない
- 長い実行では、エージェントが必要とするコマンドを開始前に許可リストへ追加しておくのが対策
- 動的ワークフローのサブエージェントは権限モードに関係なく `acceptEdits` で動作し、ツール許可リストを継承する

## NOCTAへの関連メモ
NOCTA は `bypassPermissions` を既定にしているため auto mode の分類器は経由しないが、
バックグラウンドセッションやワークフローからの実行では挙動が変わりうる。
CLAUDE.md の git 運用が「バックグラウンドセッション・自動処理・ワークフローからは push しない」と定めているのは
まさに無人実行時の判断者不在を織り込んだ設計で、この公式記述と方向が一致している。
