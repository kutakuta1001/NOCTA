## 要約（3〜5行）
CLAUDE.md / 自動メモリ / Skills / サブエージェント / MCP / Hooks の6つは、保存場所もロードのされ方も向いている用途も全部違う、という指摘。「どこに書くべきか即答できますか」という問いかけの形で、設定の置き場所を意識的に選ぶ必要性を示している。いいね3。

## 主なポイント
- 6つの設定手段はロードのタイミングが違う（常時 / オンデマンド / イベント駆動）
- 用途を間違えると、常時ロードされるべきでないものが CLAUDE.md に入る
- 公式ベストプラクティスの「ドメイン知識やときどきしか関連しないワークフローは skills へ」と同じ構造の指摘
- 自動メモリは公式機能としてドキュメント化済み（2026-07-29 処理分）

## NOCTAへの関連メモ
NOCTA はこの切り分けを既に部分的に実践している（「CLAUDE.md には常時適用ルールのみ、状況限定ワークフローはスキルに分離」という設計原則が3ファイルに明記されている）。問題は原則が守られていない点で、CLAUDE.md には SLASH COMMANDS 一覧・セッション運用表・モデル仕様の詳細といった「参照時にだけ必要な情報」が常時ロード領域に入っている。原則を追加するのではなく、既にある原則に実態を合わせる作業が必要。
