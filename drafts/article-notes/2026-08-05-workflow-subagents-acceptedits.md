## 要約（3〜5行）
権限モードはワークフローの起動プロンプトだけを制御する。ワークフローが生成するサブエージェントは、セッションのモードに関係なく**常に acceptEdits モードで実行され、ファイル編集は自動承認される**（ツール許可リストは継承する）。シェルコマンド・Web フェッチ・許可リストにない MCP ツールは実行中にプロンプトを出しうるため、長い実行では事前に許可リストへ追加しておく。`claude -p` と Agent SDK では、プロンプトする人がいないため設定済みの権限ルールに従って実行される。

## 主なポイント
- ファイル編集は常に自動承認（セッションの権限モードは無関係）
- 権限モードが制御するのは起動プロンプトの有無だけ
- default / acceptEdits では毎回プロンプト、auto では初回のみ、bypassPermissions / `claude -p` / Agent SDK ではプロンプトなしで即実行
- ツール許可リストは継承される
- 実行中に権限プロンプトが出るとワークフローは一時停止する（唯一の停止要因）

## NOCTAへの関連メモ
NOCTA は bypassPermissions で運用しているため、ワークフローは**確認なしで即起動し、その中のサブエージェントもファイル編集を自動承認する**という二重の無確認状態になる。R-02（approved/ には触れない）は論理ルールでしかないため、ワークフローのサブエージェントが approved/ を書き換える経路は技術的には開いている。`permissions.deny` に approved/ への Write を追加してハード的に守る、あるいはワークフロー利用時のみ権限モードを見直す検討が必要。
