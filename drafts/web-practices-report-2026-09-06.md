## 適用しない項目と理由

### 誤情報と確定したもの（2件）

1. **`.claudeignore` による除外設定** — 現行の Claude Code に**この仕組みは存在しない**。
   `code.claude.com/docs/ja/settings` を確認し、ignore ファイル方式は提供されていないことを確認した。
   同等の目的を果たす公式の手段は次の3つ:
   - `permissions.deny` の `Read(./secrets/**)` 形式のルール（読み取り自体を禁止）
   - `respectGitignore`（既定 `true`。`@` ファイルピッカーが `.gitignore` を尊重する。読み取り禁止ではない）
   - `claudeMdExcludes`（CLAUDE.md メモリファイルの除外専用）
2. **Claude Code Workflow Studio** — 公式ドキュメントに存在しない機能。
   実際の動的ワークフローは**JavaScript スクリプト**（`agent()` / `parallel()` / `pipeline()`）であり、
   ドラッグ＆ドロップの視覚的インターフェースではない。Gemini のハルシネーションと判断する。

### 裏付けが取れないもの（1件）

3. **`.claude/rules/` ディレクトリ** — 公式ドキュメントに記載がない。
   CLAUDE.md の `@path/to/import` 構文が同じ目的を果たし、NOCTA は既にこれを使用している
   （`/NOCTA/CLAUDE.md` が `@project_NOCTA/CLAUDE.md` を import）。

### 古い情報（1件）

4. **プロンプトキャッシュ「約5分間」** — 現在は TTL を選択できる。
   CHANGELOG v2.1.243 で `promptCacheTtl` と `subagentPromptCacheTtl` が追加され、
   メイン会話を1時間キャッシュに保ちつつサブエージェントを5分に留める構成が可能。
   ただし settings ドキュメント側にはまだ記載がなく、CHANGELOG が唯一の一次情報である。

### 数値基準の不一致（1件）

5. **CLAUDE.md「200行以内」** — 公式は行数を指定していない（「短く人間が読める状態に保つ」のみ）。
   NOCTA の基準は「SKILL.md は500行以内を目安」で、現行 CLAUDE.md 4ファイル合計は413行。
   200行という数値は出典不明のため採用しない。

### NOCTA の構成に合わないもの（3件）

6. **Ableton Live / Blender との MCP 連携** — CEO の DAW は Studio One Pro であり Ableton ではない。
   加えて R-10 により DAW 操作は CEO 自身の領域で、AI が介入しない。
7. **非エンジニアを含む全クリエイターへの推進** — スタッフゼロ型（CEO 1人＋AI エージェント）のため対象者が存在しない。
8. **Figma モックからのプロトタイプ生成・MVP の市場投入時間短縮** — Figma は未使用。
   後者は具体性のない一般論で、適用可能な行動に落ちない。

## CEOが確認すべき事項

1. **R-05 に `/compact` の発火基準（70%）を1行追加するか。** 追加すると CLAUDE.md が1行増える。
   G-07 の「これを削除すると Claude が間違いを犯すか」を適用すると、現状は基準がないため
   圧縮タイミングが Claude の裁量になっている。数値化する価値はあると考えるが、判断を仰ぐ。
2. **今回の収集の費用対効果。** 20項目中12項目が既に実装済み、5項目が誤情報・裏付けなし・古い情報だった。
   Gemini Search Grounding は NOCTA の成熟度に対して新規性の低い情報を返す傾向が出ている
   （2026-08-05 の前回レビューでも「発見10件中8件実装済み」だった）。
   クエリを「NOCTA が未実装の領域」に寄せる（例: hooks の高度な使い方・PreModelSwitch・workflow の品質パターン）か、
   このステップの実行頻度を下げる（週次→隔週）ことを検討したい。
3. **`promptCacheTtl` の設定。** 1時間キャッシュを明示設定すると長セッションのコストが下がる可能性がある。
   ただし現在のセッションは既に1時間 TTL で動作している旨がシステム側から示されており、
   明示設定が必要かは未確認。次回 `/model-review` で扱うのが適切と考える。
