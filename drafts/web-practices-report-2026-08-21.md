## 要注意: git・シェル操作に関わる提案（CEOが内容を確認してから判断）

自動適用していません。以下は Web 側の主張であり、NOCTA の慣習と衝突する箇所があります。

1. **「カスタム設定ファイル（`SKILL.md`・`.claude/settings.json`）を Git で管理してチーム全体で共有する」（クエリ4）**
   NOCTA では `~/.claude/settings.json` が API キーを平文で含むため、リポジトリにコピーしない運用です（git 運用ルールに明記）。`claude-config/` には agents / commands / references / hooks のみを置き、settings.json を含めていません。この提案はそのまま適用すると認証情報の漏洩に直結します。**適用しないことを推奨します。**

2. **「CI/CD とプルリクエストでの人間による最終レビューを必須にする」（クエリ3）**
   NOCTA の `main` への push は GitHub Actions を起動して本番サイトを更新します。PR ベースに切り替えるとブランチ運用と承認ゲートの再設計が必要です。現状は承認ゲート①〜⑨が human-on-the-loop の役割を果たしているため、**現規模では過剰と判断します。**

3. **「RTK のようなツールで CLI 出力を圧縮する」（クエリ5）**
   ツール名の出典が確認できず、インストールを伴います。外部ツールの追加は CEO の判断事項です。**代替として、上記「収集系スキルの出力量制御」で head による行数制限を使う案を提示しました**（新規インストール不要）。

4. **「`CLAUDE.md` を Git でバージョン管理する」（クエリ2）**
   これは既に実施済みです（`project_NOCTA/CLAUDE.md` が git 管理下）。git 操作の追加は不要です。

## Gemini 出力の事実誤り（レビュー時の注意）

1. **「`Plan Mode`（`/plan` または Shift+Tab）」（クエリ2）** — `/plan` というスラッシュコマンドは公式に存在しません。Plan Mode への切替は Shift+Tab（またはモード選択）です。この記述を根拠にスキルへ `/plan` を書き込むと動作しません
2. **「RTK のようなツール」（クエリ5）** — 出典を特定できませんでした。実在・用途とも未検証です
3. **クエリ4 の出力形式崩れ** — 指定した【NOCTAへの関連度】の後に【実践的なベストプラクティス】が続き、フォーマットを逸脱しています。内容は使えますが、Gemini 側の出力安定性は高くありません

3. **要注意項目1（settings.json の Git 管理）は適用しない方針で問題ないか。** API キー平文の問題があるため推奨しませんが、判断は CEO に委ねます
